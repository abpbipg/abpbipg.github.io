# BGP 高级特性

## 一、匹配路由的工具

### 1、ACL（用于匹配路由，只能使用基础 ACL）

```
ACL 使用路由前缀 + 主机位进行灵活匹配，
可以匹配奇、偶数路由（或者网段中的任意一位地址）
	
如：10.1.1.0/24  匹配  10.1.1.0/24 中的奇数路由
（permit source 10.1.1.1  0.0.0.254）
代表最后的 1 固定，前面的 7bit 都可以任意修改

    ① 10.1.1   由  0.0.0 固定，
        - 代表 10.1.1  不可改变
	② 最后的 1 二进制为： 0000 0001    ，
        - 通配符 1111  1110  代表 128、64、32、16、8、4、2 都可以任意变化，
        - 但是最后 1 固定
	③ 可以匹配 10.1.1.0/24 中的任意奇数路由
					"通配符可以匹配主机位"
```

#### ACL 缺陷：无法匹配前缀一致的路由

```
如：10.1.1.0/24 、10.1.1.0/25 无法只匹配 24 位的路由，
    - 禁止 25 位的路由
```

### 2、 IP-prefix

```
IP-prefix 可以前缀 + 掩码长度同时匹配（或者单独匹配）

10.1.1.0/24 和 10.1.1.0/25 如果只需要匹配 24 位掩码的路由
			
    ① ip ip-prefix A permit 10.1.1.0 24 less-equal 24	
    // 匹配 10.1.1.0/24 的路由，且掩码最大不超过 24
			
    ② ip ip-prefix A permit 0.0.0.0 0 less-equal 24	
    // 匹配前缀为 0.0.0.0/0 的路由，但掩码不能超过 24
```

#### 优点：可以匹配前缀和掩码，但无法灵活匹配主机位

```
例1： 匹配 10.1.1.0/24 和 20.1.1.0/24，
    - 不要 10.1.1.0/25 和 20.1.1.0/30 的路由

ip ip-prefix A permit 0.0.0.0 0 greater-equal 24 less-equal 24

// 代表匹配前缀为：0.0.0.0/0，掩码范围是：24-24 的路由
——————————————————————————————————————————————————————————————————

以上信息必须得知路由前缀、或者掩码范围才能生效，
- 在 BGP 中有数以十万甚至几十万的路由需要承载，
- 很难使用以上方式匹配路由
```

### 3、as-path-filter

```
利用 BGP 的 AS-Path 来进行匹配路由（使用的是正则表达式）
```

| 符号 |             作用             |                     解释                     |
| :--: | :--------------------------: | :-------------------------------------------: |
|  .  |    代表匹配任意字符和空格    |          （如：1、2、3、4、null 等）          |
|  *  | 代表前面的字符执行 0 或 N 次 |    （如：123* = 12、123、1233、12333 等）    |
|  +  | 代表前面的字符执行 1 或 N 次 |      （如：123+ = 123、1233、12333 等）      |
| （） |     代表里面内容完整匹配     | （如：（10）* = null、10、1010、10101010 等） |

```
BGP 的 AS 号书写方式，从右往左记录

    如：经过了 AS 100、200、300 则显示的 AS_Path（300、200、100）
```

|                                                                       符号                                                                       |            作用            |                         注释                         |                                            举例                                            |
| :-----------------------------------------------------------------------------------------------------------------------------------------------: | :------------------------: | :--------------------------------------------------: | :----------------------------------------------------------------------------------------: |
|                                                                         ^                                                                         |      代表匹配首行位置      |          （在 BGP 中代表匹配最后经过的 AS）          | 例如：匹配最后经过 AS 100 的路由				^（100）		可以匹配 AS_Path（100、200、300、400）的路由 |
| $ | 代表匹配尾行位置 | （在 BGP 中代表第一个经过的 AS） | 例如：匹配从 AS 100 发出的路由（100）$  	可以匹配 AS_Path（400、300、200、100）的路由 |                            |                                                      |                                                                                            |
|                                                                        ^$                                                                        |  代表匹配本地的 BGP 路由  |               （无 AS 号的 IBGP 路由）               |                                                                                            |
|                                                                         _                                                                         | 代表匹配 (、）、空格、{ 等 | 例如：匹配 AS 300 的路由，AS_Path（400 300 200 100） |                               `_300_` 代表匹配 300 的路由                               |

---

```
'|'  管道符代表"或"的意思			

    例如：匹配来自于 AS 100 或者 200 的路由			
    //  （100 | 200）
```

---

```
[ ] 代表匹配里面任意的字符			例如：[12]		

// 代表匹配 1 和 2 的任意字符，如：1、2、（123中的12）

例如：匹配来自于 AS 100、200、300 的路由，其他拒绝		（[123]00）
```

```
[^] 代表不匹配里面的任意字符		

例如：[^34]		

// 代表不匹配数字 3 和 4，其他都可以匹配

例如：不匹配 AS 300 和 400 但是可以匹配 100 和 200 的 AS	（[^34]00）
```

---

```
？ 代表 0 次 或 1次				

例如：10？			代表匹配 1 或者 10
```

---

```
例子：如何匹配始发于 100 或者 200 的路由
	（100|200）$

例子：过滤中间经过 AS 400 的路由
	_400_	（400)
```

#### 配置命令：

```
// 代表匹配本 AS 的路由（不带 AS 号）
ip as-path-filter 1 permit ^$								

// 代表匹配 AS 号为 1000 的路由
ip as-path-filter 1 permit _1000_							

（相同名字的 as-path-filter 关系是或，不会被覆盖，
    - 所以不需要使用的 as-path-filter 必须删除）

// 匹配本地产生的路由和 AS 号为 1000 的路由
route-policy LP permit node 10 							
 		
if-match as-path-filter 1 

// LP 值修改为：200
apply local-preference  200							

// 其他路由不做修改，直接放行
route-policy LP permit node 20 						
————————————————————————————————————————————————————————

补充：AS-path-filter 相比于其他的匹配工具

- 优势：
    - 无需匹配明细路由，可以直接针对 AS-path 生效
    - （AS-path 是公认必遵属性，路由传递时一定会携带）
			
- 缺点：
    - ① 需要掌握正则表达式的使用 
    - ② 来自于相同 AS 的路由，无法区分
```

## 一、团体属性

### 1、公认团体属性（保留的属性，具有特殊意义，能够识别团体属性的设备均支持对应的操作）

```
① internet（默认）
    - 代表该团体属性的路由，可以传递给所有的对等体

② no-advertise 
    - 代表该团体属性的路由，不能传递给任何对等体

③ no-export  
    - 代表该团体属性的路由，不能传递给 EBGP 邻居（不传递出 AS）

④ no-export-subconfed  
    - 代表该团体属性的路由，不能传递给联盟中的其他子 AS（联盟子 AS 内部使用）
```

### 2、自定义团体属性

```
可以由用户自身分配相应的属性（类似于 OSPF 和 IS-IS 的 tag）
根据属性来选择 permit 或者 deny 

格式：0-4294967295（IPv4 地址长度）
        <0-65535> : <0-65535>  
也可以为路由添加对应的标签属性（community）
```

```
例1：1.1.1.1/32 和 1.1.1.2/32 路由，禁止把 1.1.1.1/32 的路由传递给其他设备
    AR1—AR2—AR3
    （例如：AR1 把路由传递给 AR2 后，禁止 AR2 再传递给 AR3）

	AR1 配置
	acl 2000
	rule permit source 1.1.1.1 0					// 匹配 1.1.1.1/32 路由

	route-policy OA permit node 10 	
 	if-match acl 2000 							// 用于匹配 1.1.1.1/32 路由
 	apply community  no-advertise				// 为该路由添加属性

	route-policy OA permit node 20 				// 放行其他路由，不做修改（1.1.1.2/32）

	bgp 100
	peer 10.1.12.2 route-policy OA export
	peer 10.1.12.2 advertise-community			// 传递路由给 AR2 时，通过团体属性（团体属性为：可选非过渡）

	（AR2 收到路由时，1.1.1.1/32 会添加  no-advertise 属性，AR2 不会把它传递给其他对等体）
```

```
例2：使用自定义团体属性完成过滤
    1.1.1.1/32 和 1.1.1.2/32 路由，禁止把 1.1.1.1/32 的路由传递给其他设备
    AR1—AR2—AR3
    （例如：AR1 把路由传递给 AR2 后，禁止 AR2 再传递给 AR3）

	AR1 配置
	acl 2000
	rule permit source 1.1.1.1 0					// 匹配 1.1.1.1/32 路由

	route-policy OA permit node 10 	
 	if-match acl 2000 							// 用于匹配 1.1.1.1/32 路由
 	apply community  1:1						// 为该路由添加属性（自定义的团体号：1:1）

	route-policy OA permit node 20 				// 放行其他路由，不做修改（1.1.1.2/32）

	bgp 100
	peer 10.1.12.2 route-policy OA export
	peer 10.1.12.2 advertise-community			// 传递路由给 AR2 时，通过团体属性（团体属性为：可选非过渡）

	—————————————————————————————————————————————————
	AR2 配置
	ip community-filter 1 permit 1:1				// 创建团体属性 1，匹配 1:1 属性的路由

	route-policy OA deny node 10 			
	if-match community-filter 1

	route-policy OA permit node 20				// 传递路由给 AR3 设备时，1:1 属性的路由过滤，其余路由均放行通过

	bgp 100
	peer 10.1.23.3 route-policy OA export
	——————————————————————————————————————————————————
```

### 3、匹配的方式可以选择基础和高级

```
	基础（针对团体属性的编号生效。如：1:1、2:2、no-export 等）

	高级（基于正则表达式匹配编号生效）
			例如：匹配 1:1 到 3:3 的路由（还可以匹配 3:1、3:2、3:3）
			permit  [1-3] : [1-3]
	——————————————————————————————————————————————————
```

## 二、四种匹配方法的区别

### 1、ACL（可以匹配明细的路由信息，如：10.1.1.1 和 10.1.1.2 以及奇、偶数路由）

```
rule permit source  10.1.1.0  0.0.0.254				// 匹配偶数路由  10.1.1.2、10.1.1.4、10.1.1.6 等
rule permit source  10.1.1.1  0.0.0.254				// 匹配奇数路由  10.1.1.1、10.1.1.3、10.1.1.7 等

还可以匹配网段路由，例如：10.1.1.0/24 中的 0—7 的路由
rule permit source  10.1.1.0    0.0.0.7			
```

### 2、IP-prefix（可以匹配非明细的和明细的路由信息）

```
如：匹配掩码为 24 位的路由
ip ip-prefix A permit 0.0.0.0 0 greater-equal 24 less-equal 24		// 针对掩码进行匹配

如：针对相同前缀，但不同掩码的明细路由
ip ip-prefix A permit 10.1.1.0 24 less-equal 25					// 匹配 10.1.1.0/24—25 的路由（其余如：10.1.1.0/30 和 10.1.1.0/27 等都会被过滤）

以上匹配方式均需要明细路由或者掩码，如果没有具体信息无法匹配
```

### 3、as-path-filter（可以针对 AS 进行匹配）

```
可以针对公认必遵属性进行匹配（所有的 BGP 路由必须携带 AS_Path 否则会导致 Notification 报文）
并且可以不针对明细路由进行匹配，更加灵活
（缺点是无法针对相同 AS 的不同路由进行区分）
```

### 4、community-filter（可以针对自定义的编号来进行匹配）

```
如：1:1、2:2 等更加灵活
缺点是可选非传递属性（需要设备支持）
```

## 四、ORF

```
（出方向路由过滤）
BGP 有 3 张路由表，出方向路由表可以在修改完属性后再进行传递，接收方可以收到已经修改完成属性的路由
对于路由过滤而言，也可以在出方向设备过滤后再进行传递（可以节省带宽）

但是，如果出方向设备是运营商，则客户设备无法对运营商进行修改
只能在收方向路由表进行过滤，收到路由后再对这些路由进行属性修改或者过滤（会占用大量的接口带宽）

使用 ORF
作用：
    可以在接收方配置，控制发送方的路由过滤
		① 接收方可以发送 Route-refresh 报文刷新发送设备的路由表（告知对方，本端需要接收的是哪些路由）
		② 发送方可以先过滤路由后再次发出，减少带宽浪费


AR2
	ip ip-prefix A index 10 deny 1.1.1.2 32					// 过滤 1.1.1.2/32 路由
	ip ip-prefix A index 20 permit 1.1.1.1 32				// 允许 1.1.1.1/32 路由

	peer X.X.X.X ip-prefix A import						// 接收 10.1.23.2 路由时，调用 ip-prefix
  	peer X.X.X.X capability-advertise orf ip-prefix send		（使用 ORF 协商能力，告知对方发送路由前进行过滤）

AR1
	peer Y.Y.Y.Y capability-advertise orf ip-prefix receive		// 针对 AR2 的 ORF 进行协商过滤，提前过滤路由
```

## 五、对等体组

```
BGP 可以针对相同策略或属性的对等体，划入到一个对等体组中
作用：减少管理员的配置，已经便于大型 BGP 组中的对等体维护，减少不必要的路由传递（实现按照打包）
按组打包可以把需要传递给10个邻居的 N 条路由，变成 1 个对等体组 N 条路由（加快传输的速度，减少设备的路由更新数量，增加效率）

配置命令
1、创建 BGP 对等体组
    bgp 100
    group IBGP internal					// 创建一个 IBGP 的内部对等体组（用于 IBGP 邻居）

    peer 1.1.1.1 group IBGP					// 把 1.1.1.1 加入到 IBGP 组中
                                        （加入后，设备会自动产生 peer 1.1.1.1 as-number 100 的命令及 peer 1.1.1.1 enable）

2、加入到 EBGP 组（前置条件，需要先创建对应的会话）
    bgp 100
    group EBGP external
    peer 4.4.4.4 as-number 400				// EBGP 对等体需要先拥有会话后，才能添加到对应的 EBGP 组中
    peer 4.4.4.4 group EBGP

————————————————————————————————————————————————————————————
    加入到相关的对等体组后，可以批量调用命令
    peer IBGP route-policy XX import			// 该命令会针对所有的 IBGP 组中的成员生效（其他命令以此类推）
    peer IBGP connect-interface loopback0	

    查看组成员信息
    display  bgp group XXXX				// XXXX 为对等体组的名称
    display bgp update-peer-group			// 查看按组打包的更新信息（成员及相关策略信息）
```

## 六、安全性

### 1、MD5 认证

```
避免未授权的第三方设备接入 BGP（窃取路由，或者进行路由注入攻击"短时间内发送大量的 BGP 路由，占用合法设备的路由表"）
开启 MD5 认证后，会在 TCP 的 option 中添加 MD5 运算后的 hash 值，来进行保护（hash 值一致才能建立对等体关系）

bgp 100
peer X.X.X.X password simple 123				// 与 X.X.X.X 对等体建立邻居，并且开启密码认证功能（密码：123）
```

### 2、GTSM

```
攻击者设备可能会发起泛洪攻击（DOS）短时间内发送大量需要处理的报文，增加设备的 CPU 负担（导致设备不可用）
可以设置 GTSM，检查 IP 报文头部中的 TTL 值，如果不符合范围则直接丢弃，不进行下一步处理，减少 CPU 的消耗

    peer 1.1.1.1 valid-ttl-hops 5 					// 1.1.1.1 设备的 TTL 范围必须是 255—251（否则丢弃）
```

## 七、4 字节的 AS

```
2 字节的 AS 号濒临枯竭，没办法适应现有业务及网络的发展，所以 BGP 扩展了 AS 号的长度（4 字节）
2 字节 AS 范围（1—65535，但 0 保留不使用）
4 字节 AS 范围（1—65535 : 0—65535）		// 例如：1.1 = 65537（如果是 1:0 就等于 65536，. 前是 65536 的倍数，. 后的是个位数）

补充：不支持 4 字节的 BGP 设备（AS 号会以 23456 显示）
```

## 八、大型 BGP 组网

### 1、反射器

```
作用：	① 打破 IBGP 水平分割，同时添加防环属性（避免环路产生）
        ② 减少 IBGP 对等体关系（无需建立全互联）
```

#### 防环属性

```
① cluster-list（簇列表）
    RR 设备反射时，默认会把自己的 Router id 作为簇 ID 添加到 cluster list 中
    当其他 RR 设备收到该路由时，发现 cluster list 中有自己的 cluster id 则会丢弃路由（避免防环）
    作用：在反射簇间防环

② originator id
    反射簇内部防环，RR 设备第一次反射路由时，会添加 Originator id（传递路由给 RR 的设备 Router id）并且添加后，不会再修改
    如果有设备收到该路由，发现 originator id 与本地的 router id 一致，则丢弃路由
    作用：簇内防环

    也能用于选路（优选 cluster list 短的路由，如果 cluster list 一致，则比较 originator id 小的优先）
```

### 2、联盟

```
把一个超大型的 AS 划分为多个子 AS 进行管理，子 AS 之间建立 EBGP 邻居关系，子 AS 内部建立 IBGP 邻居关系

设备数量较少（AS 内 100 个设备内，可以采用反射器）
设备数量庞大（AS 内部可以超过 100-200 及以上的设备，则需要配置联盟）
```
