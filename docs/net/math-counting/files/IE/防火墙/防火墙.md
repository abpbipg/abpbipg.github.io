# 防火墙
# 一、防火墙基础
## 1、安全区域
```
（相同区域可以实现互访，不同区域需要通过安全策略）

缺省区域
① local：
    是防火墙本身
    （自身的接口都为 local 区域，如：loopback、G0/0/0、VLANIF 等）
        优先级最高（100）且优先级不能修改

② trust：
    一般用于连接内部用户（需要手工划入该区域）
        优先级：85

③ DMZ：
    一般连接服务器（可以提供内/外网服务的服务器）
        优先级：50

④ untrust：
    一般连接外部网络的接口（如：Internet）
        优先级：5

安全策略中可以配置允许高优先级区域访问低优先级区域
    -（信任程度越高，安全性越高，优先级也越高）

默认情况下防火墙设置了安全策略，
    - 所有的 IP 地址和区域都禁止互访（仅有区域内部可以互访）
```

## 2、防火墙安全策略和会话表
```
不同安全区域的接口无法实现直接互访，
    - 需要通过安全策略（安全策略中可以配置多条规则）

通过规则的流量，则可以实现互访，
    - 否则拒绝访问
    - （缺省情况下有一条拒绝访问的规则 default action deny）

例如：允许 trust 访问 untrust 区域
        security-policy				// 进入安全策略
        rule name PC2-PC3				// 创建规则，名称：PC2-PC3
        source-zone trust				// 允许源区域：trust 访问目的区域：untrust
        destination-zone untrust
        action permit
```

###	问题1：防火墙配置单向策略，允许 trust 访问 untrsut（那么数据包回复的过程中，untrust 是否能够通过防火墙到达 trust 区域）
```
解决方法：
    当数据包通过防火墙时，防火墙会根据五元组来记录数据流信息，
        - 并且生成到会话表项中
	    - （当回传的数据包能够命中防火墙的会话表项，
            - 则可以通过防火墙到达 trust 区域，
            - 无需再次匹配安全策略中的规则）

	补充：会话表项
		回传的数据包能够命中会话表，
            - 则代表是同一条数据流，允许访问
		发起的数据包 如果不能匹配安全策略中的规则，
            - 也无法匹配会话表项，
            - 则认为是攻击流量，直接丢弃
```

# 二、VRRP 双机热备份
```
为了避免单台防火墙故障，导致业务中断，
    - 可以部署双主备防火墙实现负载分担（及主备功能）
```
## 防火墙作为网关时，可以使用 VRRP 技术（实现防火墙的冗余性）
### 问题1：防火墙上行链路和下行链路都运行 VRRP 时，可能会导致来回路径不一致的问题
```
① FW1 内部接口为 master 外部接口为 backup
② FW2 内部接口为 backup 外部接口为 master	
    - 就会导致流量来回路径不一致
```
### 问题2：来回路径不一致会导致流量无法通过防火墙
```
① PC1 从 FW1 到达外网，FW1 会生成会话表项（通过安全策略后生成） 
    - " 如果回程流量能够通过 FW1 回传，则直接匹配会话表项 "
② 但来回路径不一致，会导致流量从 FW2 回传，
    - FW2 没有流量通过安全策略，也没有生成会话表项，
    - 导致回传的流量会被认为是攻击流量，直接丢弃

可以使用 VGMP 解决（VGMP 是 VRRP 组管理协议）
    - 可以实现同一个防火墙的 VRRP 同时进行切换

如：FW1 所有接口都为 Active（则 VRRP 状态为 Master）
    - 一旦 FW1 单个 VRRP 组出现故障，则直接所有接口都切换为 Standby
    - 由 FW2 的 VRRP 作为 Master 转发数据，
    - FW1 的所有 VRRP 组都切换为 Standby，
    - 确保来回路径一致（解决问题 ① 和 ②）
```

### 问题3：如果使用了 VGMP 或者其他方式依然无法保障来回路径一致，导致业务中断
```
可以使用 HRP 协议（用于同步防火墙之间配置信息和状态信息）
    ① 配置信息：
        - 防火墙安全策略，安全区域，虚拟系统等
    ② 状态信息：
        - 防火墙会话表、Server-Map、NAT 表项等	
        - " 当会话表同步后，就算来回路径不一致，
        - 也有回程表项可以匹配 " 
```




## 防火墙配置命令
```
1、基础配置命令
	firewall zone trust 							// 进入信任区域
	add interface G1/0/0						// 把 G1/0/0 接口划入信任区域

	firewall zone name HRP						// 创建自定义区域（名称：HRP）
	set priority 60								// 手工配置区域优先级（注意：默认区域无法修改优先级）
	add interface G1/0/2						// 把 G1/0/2 接口划入 HRP 区域（注意：一个接口只能属于一个安全区域）

2、安全策略
	security-policy							// 进入安全策略
	rule name A								// 创建规则：A（注意：规则按照配置的顺序来执行）
  	source-zone trust							// 允许源区域：trust 访问目的区域：untrust
  	destination-zone untrust
  	action permit

3、VRRP 双机热备份配置命令
	① 通过 HPR 协议同步不同防火墙之间的会话信息，避免来回路径不一致造成数据丢失问题
		系统配置视图下开启（双方需要建立会话信息）
		hrp enable
		hrp interface G0/0/X remote 10.1.12.2     		（指定源接口及邻居 IP 地址）
	
	② 防火墙的 VRRP 默认加入 VGMP 组，通过 VGMP 组统一控制主备链路
		interface G0/0/X
		vrrp vrid 1 virtual-ip 10.1.1.254 active     		（指定为 VRRP Master 设备）// 主设备配置

		vrrp vrid 1 virtual-ip 10.1.1.254 standby  		（指定为 VRRP Backup 设备）// 备份设备配置

	③ 配置 VGMP 组（ENSP 不支持）
		vrrp group 1
		add  interface G0/0/X vrrp vrid 1     			（把接口 G0/0/X 及 VRRP 组 1 加入到 VGMP 1 中管理）
	
	④ 配置 HRP 其他功能（可选）
		hrp mirror session enable            				（避免来回路径不一致，开启会话快速同步功能）"部分设备无需添加"
		hrp configuration auto-check      				（检查 HRP 主备配置一致性，完成配置同步）
		hrp standby-device                      				（当前设备修改为备份设备）
		hrp switch standby                       				（手工把当前设备切换为 standby）

	查看配置
		display  zone					// 查看所有的安全区域（可以查看是否把接口正确发布到安全区域中）	
		display firewall 	session  table		// 查看防火墙会话表项（摘要）	" 添加 verbose 可以查看详细信息 "	
```	


# 三、防火墙引流及虚拟系统
```
VRF（vpn-instance）虚拟路由转发，
    - 可以通过虚拟的路由表来引流数据包转发，
    - 在 MPLS VPN 中也可以区分不同客户的路由
    - （解决地址空间重叠问题）

配置 VRF 后可以生成多张路由表（RIB）、多张转发表（FIB）

防火墙也有 VRF 的概念，
    - 但防火墙除了 FIB 表以外还需要安全区域和安全策略

防火墙的虚拟系统可以把以上的功能都独立隔离
    - （每个虚拟系统都有自身的接口、安全区域、安全策略和 IP 地址等信息）

应用：
    可以在中大型的公司给不同的部门创建虚拟系统，
        - 实现一网多用

    （应用于云数据中心，给不同的客户分配虚拟防火墙，实现用户的逻辑隔离）


补充：
    防火墙虚拟系统之间都是独立隔离的，可以理解为两台防火墙互联
    （需要有物理接口才能实现互访，
        这个物理接口使用 Virtual-if 接口模拟）

        public 的虚拟接口为 Virtual-if0	，
            - 其他虚拟系统的 Virtual-if 接口根据创建的顺序分配
```
```
例1：public 配置
    
    // 允许 public 访问 RD 的 192.168.2.0/24 网段（配置访问的静态路由）
    ip route-static 192.168.2.0 24 vpn-instance RD		

例2：RD 虚拟系统内配置
    
    // 允许 RD 访问 public 的 192.168.1.0/24 网段
    ip route-static 192.168.1.0 24 public				

例3：RD 虚拟系统访问 OA 虚拟系统的 192.168.3.0/24 网段
    在 public 配置
    
    // 代表在 RD 路由表中配置 192.168.1.0/24 路由，下一跳为：OA 虚拟系统
    ip route-static vpn-instance RD 192.168.1.0 24 vpn-instance OA		
```


## 配置命令：
```
	（核心交换机配置）
	1、创建实例（VRF）
		ip vpn-instance OA
  		route-distinguisher 1:1

	2、创建 VLAN 及配置 VLANIF 接口
		vlan batch 10 20 12 192							// 创建 VLAN

		interface Vlanif10								// 核心交换设备连接防火墙（流量的出接口）
 		ip binding vpn-instance OA						// 绑定实例
 		ip address 10.1.1.2 24

		interface Vlanif12
 		ip address 10.1.12.2 24

		interface Vlanif20
 		ip address 20.1.1.2 24

		interface Vlanif192								// 连接内网终端的网关接口
 		ip binding vpn-instance OA						// 绑定实例
 		ip address 192.168.1.254 24

	3、配置引流的路由
		ip route-static 0.0.0.0 0 10.1.12.1 					// 把 OA 到达防火墙后，完成清洗的流量，引流到外部网络

		ip route-static 192.168.1.0 24 20.1.1.3				// 回程路由，把 OA 流量从外部回传时引流回到防火墙

		ip route-static vpn-instance OA 0.0.0.0 0 10.1.1.3		// 把流量从内部 OA 引流到防火墙

	4、（省略配置）
		核心交换设备的接口需要配置为 access 并且放行对应 VLAN


	（防火墙配置）
	1、开启虚拟系统
		vsys enable 

	2、创建虚拟系统
		vsys name OA
		
	3、需要把物理接口资源或虚拟接口资源（loopback、Vlanif）划入到虚拟系统 OA 中
		assign interface G1/0/0
		assign interface G1/0/1

	4、切换到虚拟系统，完成防火墙配置
		switch vsys OA
		
		interface G1/0/0								// 配置接口 IP 地址
 		ip address 10.1.1.3 24

		interface G1/0/1
 		ip address 20.1.1.3 24

		firewall zone trust								// 把连接核心交换机内部的接口配置为 trust
 		add interface G1/0/0

		firewall zone untrust							// 把连接核心交换机外部的接口配置为 trust
 		add interface G1/0/1

	5、完成防火墙策略配置
		security-policy
 	
 		rule name internet								// 允许信任区域访问非信任区域
  		source-zone trust
  		destination-zone untrust
 		action permit

		（可选）
		default action permit							// 允许所有区域和地址等互访（测试的时候可以使用）

	6、配置访问和回程路由
		ip route-static 0.0.0.0 0 20.1.1.2					// 防火墙把流量引流到外网
		ip route-static 192.168.1.0 24 10.1.1.2				// 外网回传路由，引流到核心交换设备
```
