# 一、企业广域承载网架构

## 1、分层
```
    ① 接入层
		CE 与 PE 互联的网络（企业站点或分支接入的网络）

	② 接入层
		一般根据地理位置和业务进行汇聚传输
		如：某区域的连锁的销售站点通过城域网汇聚传输

	③ 核心层
		提供高速传输和业务互访的传输网络
```

## 2、多网融合
```
	传统网络一般会通过多张物理网络来进行传输（如：生产、研发、业务办公等）
	云计算、大数据、物联网等新兴技术的产生需要的传输网络越来越多，还是以传统方式部署（① 部署难度大，成本高 ② 难以维护）

	一网多用，多网融合
	① 隔离性和安全性（控制平面：路由隔离，传输平面：数据业务隔离）
		把一张物理网络逻辑的划分为多张传输网络，每张传输网络都可以承载不同的业务（切片技术、隔离技术）

	② 业务流量的分类和网络品质的保障（不同的应用对网络要求不一，如：带宽、延迟、丢包率和抖动等，如何合理的分配资源和保障品质）
		QOS、分片技术、FlexE 等实现数据的分类和资源调用

	③ 路径规划保障、优化等，高可靠性保障（如：路径的优化，需要得知全网的链路带宽、延迟、承载量等）
		全网流量不清晰，无法精准调优
		（通过 iMaster 控制器收集网络拓扑、链路带宽、开销等信息，通过 SR、SRv6 进行转发路径的编排，实现灵活的路径调整）
		（可以通过 TI-LFA、VPN FRR 等技术来保障可靠性，BFD、SBFD 快速检测链路故障）

	④ 运维复杂，没有全网的可视化工具，无法快速进行业务下发和统一管理
		TWAMP、IFIT、iMaster 进行感知和管理，业务通过平台快速下发
```


## 路径规划
```
1、SDN 控制器（iMaster NCE-IP）+ SR（SR-MPLS 和 SRv6）
	① 收集网络拓扑信息，链路信息和网络品质参数
	② 用户通过意图选用相应的转发路径（Semgent list 和 SR policy）
	③ 通过 NETCONF、PCEP 或 SR-policy 把 Semgent list 下发到设备上
	④ 源设备（源路由）根据封装的标签（SR-MPLS）或 IPv6 地址（SRH）进行转发

2、平台会通过检测技术（IWAMP \ IFIT）收集网络品质信息，进行网络检测
	① SNMP 和网络遥测工具主动上送网络告警信息或检测信息
	② 平台通过自动或手动调整新路径，生成新的 SR list 来实现转发和网络调优
	
3、切片技术提供保障业务隔离、业务多样性的品质保障

4、可以通过图形化界面了解设备状态和网络状态
	设备状态（CPU、内存的占用率，其他硬件的检测）
	接口检测（带宽、利用率、流量的 I/O 情况），突发流量检测
	区域热点检测
```


# 二、承载网网络规划设计

## 1、物理拓扑设计
```
	核心层
	一般使用 Full Mush + 双平面架构组网
	① 如：分为 X 和 Y 平面，优先 X 平面（故障后，切换到 Y 平面）
		优先选用本地站点作为备份链路设备（X1 故障，切换到 X2）如果转发到其他数据中心，会占用其他园区的带宽，导致网络瓶颈
	② 需要考虑带宽的增长和扩展性（扩展相对较差）
	③ 安全性保障（利用协议自身的安全功能或 IPsec 等进行加密，确保安全性）

	汇聚层
	可以根据不同的业务、地理位置等进行汇聚
	① 业务汇聚（不同的数据中心，连接到同一个 DC 汇聚中心上送流量）
	② 地理位置（同城中心和同城灾备中心互联到汇聚网络，MAN 城域网来进行传输）
	③ 分支互联（把城域网和市级、县级网络连接到省干或骨干网络上）

	接入层
	可以根据业务的需求、带宽、可靠性和延迟等考虑
	① 双上行的口字形组网
		优点：
			① 成本比全互联低（带宽越高、传输距离越远，成本也越高）
			② 有冗余性，不会因为单链路或者设备故障，导致业务不可用
			③ 流量转发路径清晰，不会出现来回路径不一致的问题（维护简单）
		缺点：一般为主备网络，无法实现负载均衡，一旦主链路故障可能会影响邻旁用户的网络品质
		应用场景：对成本要求较高的组网，对可靠性和延迟要求较低
			
	② 全互联组网
		优点：
			① 可靠性更好，对角访问有最优链路
			② 可以实现负载均衡，对网络品质更有保障，单链路故障不会（较少）影响邻旁设备的网络品质
		缺点：成本交高，维护更复杂
		应用场景：对延迟和网络品质要求较高，对成本要求较低的组网（金融、证券等业务）
```

## 2、IP 规划
```
	① 连续性（10.1.1.0/30、10.1.1.3/30）不要划分为 10.1.1.0/30、20.1.1.0/30
		连续性可以便于上层设备进行路由汇总，减少路由条目（10.1.1.0/30 和 10.1.1.3/30 可以汇总为 10.1.1.0/24）
									      但（10.1.1.0/30 和 20.1.1.0/30 无法进行汇总）

	② 确保地址有余量，每个网段和位置（接入、汇聚等）都有剩余的地址空间
	③ 即使支持 VRF 在网络中也尽可能确保地址是唯一的

		注意：loopback 接口地址（IPv4 确保是 32bit，IPv6 确保是 128 bit），可以用于 BGP 邻居建立、LDP 邻居、控制面邻居等
				MPLS VPN 中，不信任非 32 位的 LSP（如果部署 32bit 的 FEC，不使用，所以必须确保 loopback 是 32bit 的）

	双栈规划
		① IPv4 
			设备互联接口（接入和汇聚、汇聚和核心等，都使用 30 位掩码，节省 IP 地址浪费）
			设备对接客户，可以根据用户数量来规划掩码（如：200 个用户，可以使用 C 类地址）

		② IPv6（及 locator 规划）
			IPv6 可以由固定前缀（8bit）+ 特殊标识 + 区域标识等进行划分（以 4bit 长度为粒度划分）
			如：区域 100，教学楼2，R1 和 R2 互联设备编号（2001:100:2:102::X/127）

			locator 的规划一般不超过 96（长度最大是 120）
			可以添加上设备标识，区域标识和应用标识等
			如：AS 100、设备 1			FC02:100:1::/96    static  32
			后续部分可以动态生成或者静态生成，一般用于标识站点和接口的 SID 都需要手工指定，避免设备或协议重启，SID 改变，便于后续维护
```

## 3、路由协议规划
```
IGP（内部网关协议）
	① OSPF 开放式的最短路径优先
	② IS-IS 中间系统到中间系统

		IS-IS
			优点：
				① 极限情况下可以支持更多的网络信息（一份 LSP 可以承载内外网的路由信息、拓扑信息等，且 LSP 可以支持分片）
				② IS-IS 区域划分灵活，只要连续的 level-2 邻居就可以组成骨干区域
				③ 区域切换灵活，一个设备最多支持 3 个区域
				④ 扩展性强，支持 IPv6、SR 等路由，都可以通过添加 TLV 支持，无需更换协议版本

			缺点：
				① 网络类型较少（支持 BMA、P2P）
				② 不支持特殊区域（可以减少网络信息的泛洪，减轻设备负担）

			总结：路由承载能力强，区域划分灵活，扩展性强，适合大型网络（如：骨干网络、运营商网络）
		--------------------------------------------------------------------------------------------------------------------------
		

		OSPF
			优点：
				① 支持多种网络类型（BMA、P2P、P2MP、NBMA）可以适应不同的组网
				② LSA 类型丰富，域内 > 域间 > 域外   type 1 > typ2，选路控制方式丰富
				③ 支持特殊区域（STUB、NSSA、totally STUB 或 NSSA）

			缺点：
				① 版本不兼容（IPv4 和 IPv6）扩展性相对较弱
				② 骨干区域必须提前划分，容易出现骨干区域被分割，不规则区域等情况

			总结：路由控制灵活，支持特殊区域（可以把性能差异较大的设备进行划分）支持丰富的网络类型（适合企业网络，小型、中型网络）

		-------------------------------------------------------------------------------------------------------------------------
	
EGP（外部网关协议）
	BGP 边界网关协议，主要用于 AS 间传递路由和控制路由
		① 承载网（骨干网络）使用独立 AS 号，内部建立 IBGP 邻居关系（使用 RR 反射路由，减少 IBGP 全互联邻居数量）
		② 客户与承载网间，建立 EBGP 邻居关系，同事客户网络最好使用独立的 AS，避免环路或防环导致的路由无法传递
			补充：路由控制一般交给 RT 来完成，export RT 用于传递路由，import RT 用于判断路由是否能够接收

		③ 双点双向（双出口场景）
			必须通过修改 BGP 优先级，防止次优路径
			IGP 引入 BGP 路由时，添加 tag。在 BGP 引入 IGP 路由时，过来带 tag 的路由

			如果是双 PE 出口，或 ISP 需要添加继承开销的属性
			使得内部的 IGP 协议能够继承 BGP 的开销值（default cost inherit-metric）
```

## 4、隧道设计
```
	广域网主要使用 SR-MPLS 和 SRv6 作为传输隧道（传统的使用 MPLS VPN）

	IPv4 网络采用 MPLS VPN 或 SR-MPLS
	IPv6 网络采用 SRv6

		① 隧道需要有一定的可视化原则（如：感知链路带宽、延迟和开销等，得知拓扑信息）
		② 隧道不宜过多，减少维护压力，和查表转发的递归压力
		③ 考虑扩展性，考虑可靠性
		④ 单条隧道的带宽不宜过大，便于流量引流和调优
```

## 5、隔离设计
```
	① 可以根据不同的部门和网络，配置 vpn-instance（VRF）本地隔离不同的路由表
	② 传递路由时，可以添加 RD 值（路由区分符，RD + IPv4 = VPNv4）
		如果只需要支持 L3 路由（可以使用 BGP 的 VPNv4 地址簇，如果需要支持 L2 和 L3 的路由，则可以选用 EVPN）

```
