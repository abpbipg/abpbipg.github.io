Hub-Spoke：
    一般由企业总部和DC作为Hub，企业各分支站点可以和Hub站点互通，分支站点之间如果需要互通，也经过Hub站点中转。适用企业的所有分支站点互访都必须要绕行总部，统一进行安全监控的业务场景。

Full-Mesh：
    企业的各站点之间均可以互通，分支和总部之间、分支站点之间如果存在业务互访关系，则数据直接交互，不需要经过中间节点。适用企业的所有站点之间的互访都需要直接互通，减少绕行总部站点时延的场景。

Partial-Mesh：
    企业的大部分站点之间可以直接交互，但是少量站点之间Underlay的WAN网络无法直接通信，需要绕行第三个站点互访，例如图中Branch1和Branch3之间通信需要绕行逃生站点HQ。

##### 无线漫游设计
###### 二层漫游设计
![1720834256909](image/中小型云管理园区网络设计/1720834256909.png)
```
二层漫游的概念
    - 终端在 AP 之间移动，终端将WIFI信号从原AP平滑切换到新AP，称为漫游
    - 终端漫游前后 SSID 相同，业务VLAN不变，终端对应网关不变
    - 漫游邻居: AP 空口探测到周围的同站点邻居，且 SSID 相同
        - 称为 漫游邻居

实现
    - 终端流量不会迂回，由漫游后 AP 直接转发流量

设计点
    - AP 的 SSID 的业务vlan要相同，同时上行交换机要放行该 VLAN
    - 漫游邻居是通过空口发现的，
        - 对 AP 部署要求比较高，连续漫游的区域AP 要相互可以探测到
    
二层漫游的实现
    1. 漫游邻居
        - AP 通过空口探测周围邻居
        - 同一个站点下，如果 SSID 相同，AP 之间能相互探测到，并认为是漫游邻居
        - 一个AP最多可以建立 64 个漫游邻居
    2. 每个 AP 都会和漫游邻居建立有线的 CAPWAP隧道（控制面隧道）用于传递漫游信息
    
    3. 漫游邻居建立，和调优组没有关系，调优组按 管理VLAN划分，二层漫游邻居按照业务VLAN 是否相同二建立

    4. 终端在 AP 上线时，AP 会将用户的MAC地址等信息同步给 AP 的所有漫游邻居
        - 如终端漫游到新的 AP（漫游后AP）
        - 该 AP 会判断该终端是否为漫游
        - 同时需要到漫游前 AP 同步用户表项（VLAN,IP,认证是否通过，授权组等）
        - 然后漫游后 AP 会生成用户表项，此时终端无需再次进行身份认证
        - 终端漫游完成后，漫游后 AP 会通知它的邻居AP
        - 以便支持终端从本AP再漫游到其他AP。此外，漫游完成后，漫游前AP会删除用户表项。
    
    5.  在二层漫游中，终端的流量不会迂回，由漫游后AP直接转发流量
```
###### 三层漫游设计
![1720835641365](image/中小型云管理园区网络设计/1720835641365.png)
```
三层漫游概念
    - 三层漫游：
        - 终端漫游前后SSID的业务VLAN不同，对应不同的网关；此时，为保持漫游用户IP地址不变，需将用户流量迂回到初始接入网段的AP。

    - 上线AP：
        - 终端在AP漫游组内首次关联的AP。

    - HAP（Home AP）：
        - 在终端初次接入网络时的上线AP 的同一个二层漫游邻居范围内，
        - 通过 Hash算法选择一个AP作为 HAP用于转发该终端的三层漫游流量。

三层漫游实现
    - 终端上线时，网络会在 候选HAP中 通过 HASH算法选择一个AP作为上线终端的HAP，当终端发生三层漫游时，三层漫游流量会转发到该HAP。此方案可防止用户三层漫游后流量都打回一个AP，产生性能瓶颈。

    - 如图所示，
        - 终端从上线AP接入，然后漫游到漫游后AP；
        - 漫游后AP会到上线AP获取用户信息，及用户对应的HAP信息；
        - 漫游后AP与HAP建立一个CAPWAP数据隧道，用户发送数据报文时，流量会通过隧道迂回到HAP；
        - 如果用户又漫游回首次上线时的二层域内，则流量不需要再迂回到 HAP，在新接入的AP上直接转发。

三层漫游设计点
    - 由于三层漫游的流量会迂回到HAP，在门厅处（入口处）尽可能规划较大的二层域，以便漫游时迂回的流量可以分散到不同的AP。

    - 每个AP仅支持64个漫游迂回的用户，3层用户比较多时，会导致漫游失败，需要下线重新上线（实际部署中根据业务VLAN的规划，同楼层/同区域尽量部署二层漫游，减少三层漫游的发生）。

```

```
云AP本质是FAT AP，
    - 各自独立，但 WLAN一些业务如调优需要集中处理，而此时又没有AC的角色，因此为了兼顾可靠性、性能，同时满足本地计算要求，需要一个类似AC的全局控制角色。

Leader AP，
    - 就是在一组AP里面选举一个能力比较强的 AP 作为Leader AP，
    - 负责整个组的全局调优功能（在一个二层域中自动选举）。

调优域的划分
    - 是基于管理VLAN自动划分的，在网络规模比较小时，一个Leader AP可以管理所有的AP
    - （高性能AP管理规格<=128、低性能规格<=50），此时只需为AP规划一个管理VLAN。
```

###### 调优方式选择
![1720836044906](image/中小型云管理园区网络设计/1720836044906.png)
```
支持三种射频调优方式
    - 自动模式
        - 指定设备根据调优时间与间隔进行周期性的全局调优；
    - 手动模式
        - 设备不会主动进行调优，用户需在iMaster NCE-Campus上手动对站点内的AP进行全局或者局部调优；
    - 定时模式
        - 指定设备仅在每天指定时刻触发全局调优。

AP上根据配置模式执行相应的调优探测，切换信道扫描周边邻居信息（扫描持续15分钟）；

AP在探测期间，每10秒会将探测到的数据上报Leader；

Leader AP每5分钟计算一次调优，共计算3次以达到算法收敛的效果；

Leader AP将调优结果下发到组内的各个AP，包括计算好的信道、功率等。
```

##### 管理层次
![1720836439606](image/中小型云管理园区网络设计/1720836439606.png)
```
网络管理的设计和要点：
    - 管理层次设计，
        - 即是否需要设计多个或多级组织机构，管理不同的站点。华为云管理支持在租户范围内设计多级或多个组织，每个组织可以管理多个站点或（子）组织，以适应大型分支机构的管理要求。
    
    - （可选）组织的规划与设计：
        - 针对大型多分支机构，需要分区管理时，可以通过划分组织来按需管理多个分支机构。

    - 站点规划：
        - 将网络管理业务相对独立的一个的网络作为站点进行管理，可以是一个独立的园区/分支网络，也可以是园区/分支网络中一个相对独立的网络，如某栋楼的网络，甚至某层楼的网络。站点可以根据管理的实际需求进行灵活规划。
    
    - 网络管理员的权限设计，即分权分域设计。
```
