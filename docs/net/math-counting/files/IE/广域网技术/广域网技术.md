# 广域网技术
```
根据不同的覆盖范围可以把网络分为以下几种类型

1、局域网：一般覆盖范围几百米到几公里以内
	（如：园区网络、家庭网络、办公网络和校园网等）

2、城域网：一般是指城市之间互联的网络
	（如：地市、城区互联的网络，城市间互联）

3、广域网：覆盖范围十几公里到上千公里范围
	（如：省干网络，国干网络等）
```

## 一、企业广域网互联

### 1、自建：
```
一般是大型的企业（如：金融机构、银行证券等，电网、运营商都有自己搭建广域网的能力）	
```
### 2、租用：
```
餐饮和部分连锁企业，没有自建能力的都会租用运营商网络
```
#### 运营商专线
```
① 光纤：
	裸光纤由运营商租用给用户（用户使用纯光纤资源）网络品质和安全性都可以得到保障
	
    （专用网络，网络品质可以得到保障，安全性由运营商来提供，物理隔离）

② MPLS 专线
	通过运营商搭建的 MPLS 网络实现专用传输（一般为逻辑隔离）
	如：
        使用 vpn-instance + MPLS 技术实现逻辑隔离，实际上底层网络还是共享网络
	
    网络品质可以通过运营商的 QOS 来进行保障（或切片）网络的安全性由运营商提供
```

#### 企业自主搭建
```
企业租用 internet 资源（宽带套餐）
	用户使用 internet 网络来进行传输，但是 internet 安全性较差，所以需要通过 IPSec 来保障传输的安全性
	（IPSec 提供了数据加密、身份认证，完整性校验等功能）
	网络品质无法保障，安全性较高（由 IPSec、SSL 等技术提供）
	如：IPSec VPN、L2TP、DSVPN 等技术

一般企业都会进行混合组网
如：连锁的零售企业
	一般客户的销售系统会使用 internet + VPN 技术实现传输，重要的数据（如：财务、后台资源等）则通过租用 MPLS 专线传输，实现混合组网
```

### 3、自建的 VPN 分类
```
Access VPN（主要用于用户终端接入企业网络，如：出差员工，分部员工接入总部网络）
    常见的技术：PPTP、L2TP、IPSec 等

企业互联网络（主要用于企业网关互联，如：路由器、防火墙等）
    常见的技术：GRE、DSVPN 等

Extranet VPN（一般是扩展协议接入，如：SSL 使用 https 来进行传输）
    常见的技术：SSL VPN
```



## 三、L2TP
### 1、L2TP 角色
```
① LAC（L2TP 接入集中器）可以与 LNS 设备建立 L2TP 隧道（该设备可以是 NAS 服务器、终端或路由器等设备）
    该设备具有 PPP 和 L2TP 协议处理能力

② LNS（L2TP 网络服务器）是 LAC 对端设备，
    - 能与 LAC 建立 L2TP 隧道一条 L2TP 隧道能够包含多个 L2TP 会话
    - （LAC 可以发起建立多条 L2TP 隧道使数据流之间相互隔离，即：LAC 可以承载多条 L2TP 连接）
    
    - 多个会话通过 session ID 区分，隧道通过 tunnel ID 区分
```
### 2、消息类型	
```
控制消息用于 L2TP 隧道和会话连接的建立、维护和拆除
	补充：
        控制信息是可靠的的（用于协商会话 ID）

	数据信息通过 PPP 数据帧封装，并在 L2TP 隧道上传输
	
    所以能够支持 PPP 功能（如：IP 地址获取、CHAP 和 PAP 的身份认证等）
	
    补充：
        使用 UDP 传输，可靠性无法保障
```
	
### L2TP 传输 PPP 报文前需要先建立 L2TP 隧道和会话
```
工作过程：
	1、隧道建立过程
		① LAC 收到远端用户发起的 PPP 协商（PPPoE 拨号）请求时（或 LAC 需要宇 LNS 发起隧道建立）LAC 会向 LNS 发起 L2TP 隧道请求
		② LAC 和 LNS 之间通过 L2TP 的控制消息（协商隧道 ID、隧道认证等内容）协商成功后则建立起一条 L2TP 隧道，由协商的隧道 ID 进行标识

	2、会话建立过程
		① 如果 L2TP 隧道已存在，则在 LAC 和 LNS 之间通过 L2TP 的控制消息，协商会话 ID 等内容，否则先建立 L2TP 隧道
		② L2TP 会话中携带了 LAC 的 LCP 的协商信息（PPP LCP 协商信息）和用户认证信息
		③ LNS 收到 LAC 的信息后进行检查，若认证通过，则通知 LAC 会话建立成功，L2TP 会话则由会话 ID 进行标识

	3、用户数据传输
		① L2TP 会话建立成功后，PPP 终端将数据报文发送至 LAC
		② LAC 根据 L2TP 隧道 ID和会话 ID 等信息，进行 L2TP 报文封装，并发送到 LNS 设备
		③ LNS 收到后，对 L2TP 报文进行解封装处理，并最终根据源数据包的目的地址查路由转发到目的主机上，完成传输
```

### L2TP 应用场景
```
1、终端到 LNS
    如：
        出差员工（终端支持 L2TP 功能）可以使用 L2TP 协议与企业总部的 LNS 进行接入
    
    - LNS 完成对接入员工的身份认证和 IP 地址分配，
    - 同时支持配合 ACL 进行接入员工的访问管理

2、分支和总部的设备互联：LAC 和 LNS 可以是出口路由器设备，
    - 分支设备的 LAC 与总部 LNS 之间建立 L2TP 隧道
    - 并把分支用户的数据承载到 L2TP 隧道上进行传输
    - （LAC 与 LNS 需要通过虚拟拨号接口建立）

L2TP 
优点：
    可以使用终端、路由器、NAS 等设备接入上网
    -（特别是终端设备，便于出差员工使用 VPN 接入到公司内网）
缺点：
    无法支持组播数据传输（一般路由器不支持）无法建立邻居关系，
    - 和传递分部和总部间的路由，"配置复杂，无法动态建立隧道"
```

### 配置命令：
```
前置配置，LAC 和 LNS 建立邻居的接口必须可达（也就是必须有一个可达的公网 IP 地址）

（LAC 配置）
① 开启 L2TP 功能
	l2tp enable                                                                                	// 全局开启 L2TP 功能
	
② 设置 L2TP 组
	l2tp-group 1                                                                                  	// 配置 L2TP 组
	tunnel  password  cipher  Huawei@123                                        // 设置隧道密码：Huawei@123
	tunnel name lac                                                                              // 定义隧道名称：LAC
	start  l2tp  ip  X.X.X.X  fullusername  huawei                                	// 指定 LNS 服务器 IP 地址，并设置触发 L2TP 认证的用户名

	（补充：该 X.X.X.X 地址为 LNS 地址，且必须可达）
		LNS 地址最多可以配置 4 个，按顺序配置优先
	
③ 创建虚拟接口模板
	interface Virtual-Template1                                                           	// 设置虚拟接口模板（1）
	ppp chap user huawei                                                                    	// 设置通过 LNS 认证的 CHAP 用户名：huawei
	ppp chap  password  cipher  Huawei@123                                    // 设置 CHAP 用户密码：Huawei@123 
	ip address ppp-negotiate                                                            	// 地址通过 PPP 协商获取（服务器必须配置 IP 地址池）

	l2tp-auto-client enable                                                           	// 补充：该命令最后配置，开启 L2TP 用户的自动协商
	
	
（LNS 配置）
① 开启 L2TP 功能
	l2tp enable                                                                         		// 全局开启 L2TP 功能

② 配置 AAA 模板（添加用户）
	aaa
	local-user  huawei  password  cipher Huawei@123                    	// 进入 AAA 视图，创建用户并配置密码
	local-user  huawei  service-type  ppp                                        	// 该用户用于 PPP（CHAP）认证         

③ 设置 IP 地址池
	ip pool A                                                                                      	// 设置 IP 地址池
	network 100.1.1.0  mask  24                                                           // 地址池为：100.1.1.0/24
	gateway-list  100.1.1.254                                                     		// 设置网关地址（为 LNS 虚拟拨号模板接口地址，用于 LAC 终端接入访问）

	（分配公司内部的 IP 地址，如：192.168.1.0/24）

④ 设置模板
	interface Virtual-Template1                                                             // 设置虚拟接口模板（1）
	ppp  authentication-mode  chap                                                     // 开启 CHAP 认证
	remote  address  pool  A                                                                  // 通过认证的用户能够通过地址池 A 获取 IP 地址
	ip  address  100.1.1.254  24                                                              // 接口地址 100.1.1.254/24（地址 A 的网关地址）
	
⑤ 设置 L2TP 组
	l2tp-group 1                                                                                  	// 设置 L2TP 组
	allow l2tp virtual-template  1  remote  lac                                   	// 接收任何对端设备发起的 L2TP 请求，设置本地使用的虚拟模板，允许呼叫 LAC 名称
	tunnel  password cipher Huawei@123                                          // 设置隧道密码：Huawei@123 与 LAC 一致即可
	tunnel  name  lns                                                                          	// 隧道名为：LNS
```



## 四、GRE 隧道
	用于总部和分支设备间（路由设备）建立邻居，传递和学习路由
	GRE 能够支持多种类型的流量（如：IPv4、IPv6、广播、组播等流量）
	常用于企业间透传路由和数据

	缺陷：
		① 数据包明文传输，安全性差
		② 对身份不做校验，只要接入即可完成隧道建立（容易遭受 IP 源欺骗攻击，攻击者仿冒合法隧道的 IP 地址发起访问）
		③ 隧道的状态无法检查，只能根据目的路由是否可达判断
		④ GRE 需要手工指定隧道的源、目 IP 地址，只能 1：1 传输隧道（配置量大，难以维护）
		
	key（关键字）
		可以在 GRE 的头部中，添加 option 字段，携带 4 字节长度的关键字
		如：123、4569009 等（长度可改）
		双方收发数据时会检查 Key 字段是否一致，但 Key 字段是明文传输

	检验和
		可以提供认证功能，数据包发送时会把数据字段 + GRE 头部进行运算，生成校验和 A（发送给对端设备）
		对端设备收到数据包后，会重新进行计算（数据字段 + GRE 头部，生成校验和 B）
		对比两次结果 A = B 认证通过，合法可以接收
				      A ≠ B 则认证失败，丢弃数据包
		防止数据包被篡改

	keep alive
		补充：GRE 隧道只要源、目地址可达，状态就为 UP
		（但实际上，可能隧道已经无法转发数据包，但是状态依旧为 UP）
		可以在 GRE 上开启 keep alive 检查（默认：5s 检查一次，超过 3 次没有收到响应，则认为隧道 DOWN）
		使得 GRE 也能检查隧道状态

DSVPN
背景：传统的 GRE 技术只能点对点建立传输隧道（无法在一条隧道内，配置多个目的 IP 地址）
		使用 DSVPN 可以实现  "点对多点" 的隧道建立
		（一般总部作为 HUB 点，分支机构配置 Spoke 点，分支可以通过总部设备学习 GRE 隧道建立的路由，实现互访）
	
配置命令：
	GRE 配置命令（DSVPN）
	1、HUB 设备配置
		① 创建隧道并配置相关隧道协议类型
			interface Tunnel0/0/0
			tunnel-protocol gre p2mp
			ip address  X.X.X.X + 掩码					// 指定 GRE 为 P2MP 类型，并且配置隧道 IP 地址
		
			② 配置隧道源 IP 地址
				source G0/0/0  或（1.1.1.1）				// 指定物理接口地址或 IP 地址（必须是互联设备可达的 IP 地址）
					
			③ 开启 NHRP 协议
				nhrp entry multicast dynamic 			// 使用 NHRP 自动注册功能（组播注册）
				ospf network-type broadcast				// 使用 OSPF 协议时，接口类型需要改为广播类型（默认隧道为 P2P 类型）  	
		
		
	2、Spoke 设备配置
		① 创建隧道并配置相关隧道协议类型
			interface Tunnel0/0/0
			tunnel-protocol gre p2mp
			ip address  X.X.X.X + 掩码				// 指定 GRE 为 P2MP 类型，并且配置隧道 IP 地址
		
		② 配置隧道源 IP 地址
			source G0/0/0  或（1.1.1.1）				// 指定物理接口地址或 IP 地址（必须是互联设备可达的 IP 地址）
	
		③ 开启 NHRP 协议
			nhrp entry X.X.X.X Y.Y.Y.Y register			// 设置 NHRP 注册（静态指定 IP 地址）
												X.X.X.X 为 HUB 的隧道地址，Y.Y.Y.Y 为 HUB 的物理接口通信地址
			
			ospf network-type broadcast				// OSPF 的接口类型修改为 BMA
			ospf dr-priority 0						// 为了避免 Spoke 节点无法同步 LSA 信息，需要保证 HUB 设备为 DR
												（因为 Spoke 设备必须经过 HUB 互访）
		
	3、查看配置命令
		display ospf peer brief
		display nhrp peer all						// 查看 NHRP 协议的邻居状态



## 五、IPSec（IP Security）
	可以为 IP 网络在传输过程中提供：① 认证、② 加密、③ 完整性校验、④ 防重放攻击

	1、认证：避免数据包在传输过程中被篡改（如：植入病毒、伪造数据和修改原始数据内容）

	2、加密：避免数据包在传输过程中被窃取（如：被抓包分析数据内容，导致信息泄漏）
			① 对称加密：使用相同的密钥（公钥）进行加密和解密的，称为对称加密
				优点：传输效率高（解密过程时间更短）
				缺点：公钥再协商过程中（需要进行交互）容易泄漏，一旦泄漏安全性无法保障

			② 非对称加密：使用公钥加密，私钥解密的，加密和解密使用的密钥不同，为非对称加密
				优点：安全性更高，不怕公钥被窃取
				缺点：传输效率低（解密过程更耗费时间）

				例如：客户机和服务器需要交互数据包，数据包使用的公钥为（X）
					   服务器传递公钥 X 给客户机时，先使用非对称密钥对公钥 X 进行加密（使用 Y 对 X 公钥进行加密）
					   客户机收到后，使用私钥 Z 来进行解密，得出公钥 X
				
				先使用非对称密钥对会话密钥进行加密
				后续传输数据包时，使用会话密钥来进行对称加密，既可以确保密钥交互的安全性，又可以确保数据包传递过程中的效率

	3、IPSec 还可以提供身份认证功能
		如：密码认证，用户需要通过用户名和密码才可以发起访问
		如果无法通过身份认证，则该数据包不会处理

	4、重放攻击
		攻击者通过窃取合法用户发出的数据，重复发送来通过认证
		通过加密序列号，来防止重放攻击（加密序列号每经过一次发送都会修改，避免数据重复）


IPSec 支持两种认证协议
1、AH（认证头）协议号：51
		① 数据包完整性校验、② 身份验证、③ 防重放
		AH 不支持 IPSec 隧道穿越 NAT，只能公网使用，或私网使用
		（补充：AH 会对整个 IP 报文进行认证，避免数据包被篡改，但 NAT 必须转换 IP 地址或端口号，则无法通过认证）

2、ESP（数据安全载荷）协议号：50
		① 数据包完整性校验、② 身份验证、③ 防重放、④ 加密
		ESP 支持 IPSec 隧道通过 NAT 转换后的私网与公网互通
		（补充：ESP 只对 Data 和 ESP 的尾部进行认证，不对 IP 头进行认证，可以通过 NAT 转换）


IPSec 的工作过程
（主模式）
1、先使用 IKE 进行协商，IKE 隧道建立完成后，再利用 IKE 的加密隧道传输 IPSec 的协商信息
	① 双方互相发送 IKE 安全提议（包含：认证算法、加密算法等信息）
	② 双方筛选算法是否能够匹配，如果可以匹配则进行响应，否则协商失败

2、IKE 协商完成相关的认证和加密算法后，交互密钥生成信息
	① 双方交互密钥生成信息（如：素数、质数等）
	② 收到密钥生成信息的一方会生成公钥和本地私钥

3、交互身份信息
	① 密钥生成完成后，使用公钥对身份信息（用户名、密码等）进行加密传输
	② 设备收到数据后，使用本地私钥进行解密，得出用户信息，并且进行校验（身份验证是否合法）

	身份信息验证通过后，IKE 协商完成（完成了 IPSec 的第一阶段）

4、进入 IKE 协商的第二阶段（快速模式）
	① 双方使用 IKE 的密钥（公钥）对 IPSec 的安全提议进行加密，并传输给对端
	② 双方使用本地私钥解密后，协商安全提议（如：认证算法、认证协议 "AH、ESP"、加密算法等）
            还会传递用户身份信息及密钥生成信息

	③ 双方协商通过，且身份验证通过后会根据密钥生成信息，计算出用户数据转发时进行加密的公钥（IPSec 公钥）
	④ 后续转发的用户数据包都可以使用 IPSec 的公钥来进行加密和解密
		（完成第二阶段协商）

补充：野蛮模式
	   IKE 的第一阶段，使用快速的方式来进行交互，直接发送用户身份信息，对用户身份信息不做加密
	   ① 双方互相发送 IKE 的安全提议、密钥生成信息、用户身份信息
	   ② 收到对端的安全提议和密钥生成信息后，还需要检查用户身份信息，如果用户身份信息正确，且参数能够接收则生成密钥
	   ③ 发送验证数据（如：身份信息和结果）完成第一阶段
	
	   完成后进入第二阶段，第二阶段使用野蛮模式生成的密钥进行加密传输，和主模式一致

	   优点：交互的步骤更少，协商过程更快
	   缺点：用户身份信息没有保障，明文传递

	
IKEv2 
	通过建立一个 IKE SA 来建立一对 IPSec SA，IKEv1 需要经历两个阶段，至少交换 6 条消息
	而 IKEv2 在保证安全性的前提下，减少了传递的信息和交换的次数从而提升协商速度

	初始阶段：
		① 双方互相发送 IKE 的安全提议、密钥生成参数进行协商
		② 双方协商通过会生成密钥（IKE 密钥）
		
		③ 使用 IKE 的密钥传递用户身份信息（加密传输）
		④ 双方协商通过后完成 IKE 第一阶段协商，开始传递 IPSec SA

	子交换阶段
		① 使用 IKE 的密钥信息加密 IPSec SA 信息进行传输（也可以根据 IKE 协商的信息生成 IPSec 的密钥）
		     补充：如对安全性要求高的用户，可以进行 IKE 重认证（重新生成 IKE 密钥，并且 IPSec 密钥信息也会重新进行协商）
		② 双方通过协商生成 IPSec 密钥，用于传输用户数据


	配置命令：
		补充：AR1、AR2、AR3 使用任意的 IGP 协议，实现互联接口可达

		① 配置 IPsec 安全提议（双方设备均需要配置安全协议）
			ipsec proposal A                                                           	// 创建安全提议模板：A
			esp authentication-algorithm sha2-256                  	// 设置封装方式和认证算法（ESP 封装及使用 SHA2-256 认证算法）
			esp encryption-algorithm aes-128                          	// 设置加密算法（只有 ESP 封装模式才能进行加密，AH 模式无法配置加密算法）
			
		② 配置 IKE 安全提议（双方均需要配置 IKE 安全提议）
			ike proposal 1                                                               	// 配置 IKE 安全提议（编号：1）
			encryption-algorithm aes-cbc-128                            	// 配置 IKE 安全提议使用的加密算法（AES-CBC-128）
			authentication-algorithm md5                                   	// 设置 IKE 加密算法（MD5、SHA2-256 等）
			
		③ 创建 IKE 对等体模板，并指定 IKE 等级（双方均需要配置 IKE 对等体模板）
			ike peer A v1                                                                  	// 创建 IKE 对等体模板 | 名称为：A |  版本为：v1 版本
			pre-shared-key cipher Huawei@123                         	// 设置预共享密钥：Huawei@123
			ike-proposal 1                                                                	// 调用 IKE 安全提议（编号 1）
			remote-address X.X.X.X                                                	// 指定 IKE 对等体 IP 地址（注：该地址必须可达，最好是物理接口地址，如：10.1.23.3）
			
		④ 创建安全策略并绑定模板（IKE 对等体模板、IPsec 安全提议、感兴趣流）
			ipsec policy A 10 isakmp                                               	 // 创建安全策略模板，名称：A、序号：10、用于 IKE 的 SA 协商（动态模式） 
			ike-peer A                                                                        // 调用 IKE 对等体模板：A
			proposal A                                                                       // 调用 IPsec 安全提议
			security acl 3000                                                            	// 匹配需要保护的流量（使用 ACL 匹配 "必须为高级 ACL"）
		
		⑤ 匹配感兴趣流（需要保护的流量）
			acl 3000  
			rule 10 permit ip source 192.168.1.1 0 destination 192.168.2.2 0                 	// 例如：ACL 3000 匹配用户设备
																			（源：192.168.1.1、目的：192.168.2.2）的 IP 流量
			补充：不需要匹配的流量使用 deny 即可，需要先创建 ACL 才能绑定到 ④ 模板中
			
		⑥ 进入流量发出的接口调用模板
			interface G0/0/0
			ipsec policy A									// 调用 IPSec 模板

		查看配置
			display  ipsec sa brief                                                      // 查看 SA 摘要信息（如：IKE 对端设备 IP 地址、认证算法和加密算法等）
			display  ipsec policy brief                                               // 查看 IPsec policy 模板摘要信息（如：匹配的感兴趣流、IKE 对等体模板等）



	GRE over IPSec 配置命令                          
	（GRE 则无需匹配感兴趣流，使用以下模板，并直接在 Tunnel 中调用）
		① 配置 IPsec 安全提议（双方设备均需要配置安全协议）
			ipsec proposal A                                                           	// 创建安全提议模板：A
			esp authentication-algorithm sha2-256                  	// 设置封装方式和认证算法（ESP 封装及使用 SHA2-256 认证算法）
			esp encryption-algorithm aes-128                           	// 设置加密算法（只有 ESP 封装模式才能进行加密，AH 模式无法配置加密算法）
		
		② 配置 IKE 安全提议（双方均需要配置 IKE 安全提议）
			ike proposal 1                                                               	// 配置 IKE 安全提议（编号：1）
			encryption-algorithm aes-cbc-128                            	// 配置 IKE 安全提议使用的加密算法（AES-CBC-128）
			authentication-algorithm md5                                   	// 设置 IKE 加密算法（MD5、SHA2-256 等）
		
		③ 创建 IKE 对等体模板，并指定 IKE 等级（双方均需要配置 IKE 对等体模板）
			ike peer A v1                                                                  	// 创建 IKE 对等体模板 | 名称为：A |  版本为：v1 版本
			pre-shared-key cipher Huawei@123                        	// 设置预共享密钥：Huawei@123
			ike-proposal 1                                                                	// 调用 IKE 安全提议（编号 1）
			（无需指定对端 IP 地址，使用隧道地址即可）
			
		④ 配置安全框架
			ipsec profile A                                                                 // 创建 IPsec 安全框架，名称：A
			proposal A                                                                       // 绑定 IPsec 安全提议模板（①）名称：A
			ike peer A                                                                        // 绑定 IKE 对等体模板，名称：A
		
		⑤ 调用安全框架
			interface Tunnel0/0/0
			Ipsec profile A
		
		查看命令
			display  ipsec profile brief                                            // 查看 IPsec 框架摘要信息（如：建立情况和对等体 IP 等信息）

## 六、NAT 

源 NAT（实现私网设备访问公网设备，把 IP 头部的 "源 IP 地址" 进行转换）
	① 静态 NAT		1:1 转换
	② 动态 NAT		1:1 转换（可以配置多个 IP 地址作为地址池，地址池内的 IP 可以 1:1 转换）
	③ NAPT			1:N 转换（可以配置多个 IP 地址作为地址池，地址池内的 IP 可以 1:N 转换，同时转换端口号，使用端口号来实现地址复用）
	④ EASY IP		1:N 转换（无需配置 NAT 地址池，使用公网接口的 IP 地址作为转换，同时也需要使用端口号来实现地址复用）


目的 NAT（实现公网设备访问私网设备，把 IP 头部的 "目的 IP 地址" 进行转换）一般用于公网用户访问内部服务器
	补充：使用目的 IP 地址、端口号来进行 1:1 的映射


UNR（用户网络路由）
	当 NAT 转换的设备非公网出口，则改转换设备需要把转换后的路由生成 UNR 路由，用于公网设备回传数据包
	（自动生成，也可以引入到路由协议中）


	NAT 的缺陷
	1、完全圆锥形 NAT（只要目的 IP 地址和端口号一致，即可实现转换。
	   （攻击者可以利用抓包获取转换后的目的 IP 地址和端口号，就可以通过该目的地址和端口号，发起访问攻击）

	2、限制圆锥形
		① IP 限制：数据包必须目的 IP 地址、端口号一致，并且源 IP 地址也需要和 NAT 转换前的一致才能进行 NAT 回传
		② 端口限制：数据包必须目的 IP 地址、端口号一致，并且源 IP 地址、源端口号也需要和 NAT 转换前的一致才能进行 NAT 回传
		安全性较高，一般是 NAPT 和 EASY IP 使用
		（但攻击者也可以通过补抓数据包来发现转换后的 IP 地址、和端口号）
