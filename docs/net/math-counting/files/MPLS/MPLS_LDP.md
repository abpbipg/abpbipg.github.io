# MPLS LDP （标签分发协议）
```
作用：
    专用于 MPLS 分配标签协议
    工作在传输层（使用 UDP 和 TCP 传输协议，端口： 646）
```

## LDP 报文（常用）
```
1、hello 报文：用于发现邻居，和传递 LDP 的传输地址
——————————————————————————发现阶段

2、Initialization 报文：用于协商邻居参数
3、keepalive 报文：用于维持邻居关系（周期性发送）
——————————————————————————会话建立阶段

4、Address 报文：用于通告设备自身的接口 IP 地址（一般为 32 位）
5、Label Mapping 报文：为 32 位 IP 地址分配标签
——————————————————————————通告阶段
```

## LDP 工作过程
```
1、运行了 MPLS LDP 的设备会主动发送 hello 报文（用于发现邻居，传输通信地址）目的 IP 地址：224.0.0.2（所有路由节点组地址）

2、交互传输地址后，由 IP 地址大的一方发起 TCP 三次握手，握手成功后进入会话阶段

3、会话阶段，双方会交互初始化报文，协商参数信息（如：LDP 的版本、（标签的分发方式、保持方式、控制方式等）、标签空间等信息）
	如果同意则回复 keepalive 报文，代表会话建立成功（协商通过）
	如果不同意，则直接回复 notification 报文，中断 TCP 连接

4、如果会话阶段协商成功，则进入通告阶段
	交互标签报文，为特定的 FEC 生成标签
	（还可以为失效的 FEC 撤销标签）
```

## LDP 标签分配、控制 和 保持方式
### 1、标签分配方式
```
① 下游自主方式（Downstream Unsolicited，DU）对于特定的 FEC，无需上游邻居请求，本设备自动为 32 位的主机路由分配标签
    优点：下游自主方式，LSP 建立速度快，无需上游邻居请求（快速自主建立 LSP）
    缺点：浪费标签空间（无论是否上游邻居需要的标签，都会自主产生和推送）

② 下游按需方式（Downstream on Demand，DoD）对于特定的 FEC，需要收到上游邻居的请求，下游设备才会生成和推送标签
    优点：节省标签空间，LSP 可以按需建立
    缺点：建立速度慢
```

### 2、标签分配控制方式
```
① 有序方式（Ordered）对于特定的 FEC，从下游邻居收到标签后，才会继续往上游推送标签
    优点：可以确保 LSP 按顺序建立（完整建立）
    缺点：LSP 建立速度慢

② 独立方式（Independent）对于特定的 FEC，无需从下游邻居收到标签，也能继续往上游推送标签
    优点：LSP 建立速度快
    缺点：LSP 可能会不完整（如：中间设备没有 FEC "路由" 导致 LSP 断开）
```

### 3、标签保持方式
```
① 自由方式（Liberal）对于特定的 FEC 无论是否最优下一跳的标签，都会接收
    优点：可以联动 IP FRR 等功能，能够快速实现故障切换，减少收敛时间
    缺点：浪费标签空间，无论是否最优下一跳标签都会保留

② 保守方式（Conservative）对于特定的 FEC 只接收最优下一跳的标签，次优标签不会保留
    优点：节省标签标签空间，减少 LSP 维护
    缺点：故障切换速度慢（收敛速度慢）

华为的标签分配、控制和保持方式默认组合
下游自主 + 有序方式 + 自由保留
```

## LDP 标签分配过程及数据包转发过程
### 1、默认华为的设备（采用：下游自主 + 有序方式 + 自由保留）
```
主动为本地的 32bit 主机路由生成标签（3 号标签，默认启动 PHP 特性）
```

### 2、根据路由的传递方向，传递标签信息
```
	IN 代表本地产生的标签，OUT 代表邻居传递的标签
	例如：AR1-AR2-AR3-AR4 互联
	AR1 会为本地的 1.1.1.1/32 FEC 产生标签（IN 3 / OUT NULL）并传递给 AR2
	AR2 接收后，会生成出标签（IN NULL / OUT 3）代表 AR2 收到的标签，同时 AR2 如果存在 1.1.1.1/32 的路由，也会产生标签
	AR2 产生新的标签（IN 1024 / OUT 3）并且推送给 AR3，如此类推
```

### 3、AR4 获取到 1.1.1.1/32 的路由及标签后，可以实现标签转发
```
① AR4 会查看 FIB 表项，到达 1.1.1.1/32 如何转发，发现 tunnel id 为 0x非0（如：0x1）代表使用隧道转发
② AR4 会根据 tunnel id 找到相应的隧道（token id）
    根据 ingress 及动作 PUSH 压入标签（如：1025），并根据标签映射的出接口和下一跳进行转发

③ AR3 设备收到后，会直接查看 ILM 根据入接口、入标签找到对应的标签动作和出标签
    把 1025 标签转换为 1024 标签，并根据 1024 标签找到 NHLFE（下一跳标签转发表）
    NHLFE 有（下一跳、出接口等信息，指导数据包如何转发）

④ AR3 把数据包发送给 AR2 后，AR2 查看 ILM 把 1024 标签更换为 3 号标签，同时触发 PHP 特性，弹出 3 号标签
    弹出 3 号标签前，会根据 3 号标签的信息查看 NHLFE 找到如何把数据包发送给 AR1 的出接口和下一跳地址

⑤ 最终 AR1 收到不带标签的数据包（纯 IPv4 报文）
    AR1 根据 FIB 表找到具体接口
```

## PHP（次末跳弹出）
### 隐式空标签（3）
```
当数据包封装为 3 号标签时，会提前弹出 3 号标签进行转发
    作用：
        减少最后一跳设备的查表压力（减少一次 MPLS 查表，直接根据 FIB 转发即可），还能节省标签空间
    缺点：
        无法保障次末跳的服务质量，也无法针对标签实现策略控制
```

### 显式空标签（0）
```
数据包可以把标签 0 保存到最后一跳再弹出（不使用 PHP 特性）也能节省标签空间
```

## 配置
```
（MPLS LDP 邻居建立前，需要保障各节点的 LSR-ID 可达）
1、配置 MPLS LSR-ID
	mpls lsr-id X.X.X.X					// 指定 MPLS LSR-ID，该 ID 可以为 loopback0 接口
								（补充：该接口必须可达，用于作为 LDP 的传输地址，不可达会导致 LDP 无法建立）
2、开启 MPLS 及 MPLS LDP 功能
	mpls
	mpls ldp						// 全局开启

3、进入 MPLS 流量经过的接口，开启 MPLS 及 MPLS LDP 功能
	interface G0/0/X
	mpls 
	mpls ldp						// 接口配置

查看配置
display mpls ldp peer						// 查看 LDP 邻居
display mpls lsp						// 查看 LSP 隧道信息（只显示有效的 LSP）
display mpls lsp verbose						// 查看详细的 LSP 信息（如：FEC、下一跳、出接口、标签动作等）

display mpls ldp lsp						// 查看所有 LDP 生成的 LSP 信息


如果是非公网的 IP 路由，需要添加递归隧道的命令
route recursive-lookup tunnel
```
