# 路由策略与路由控制
```
    路由策略：
        针对路由条目进行控制的（控制平面）能够对路由条目进行 ”过滤、修改属性、开销值、优先级等 “ 修改的信息，能够出现在路由表项中

    策略路由：
        针对数据包进行控制（转发平面）能够对数据包进行 ”过滤、重定向、修改 QOS 优先级、限制流量等操作“ 无法体现在路由表项中，优先于转发表
```	

## 一、匹配工具
### 1、ACL（访问控制列表）
```
    能够通过路由前缀和通配符匹配前缀信息（可以用于路由策略和策略路由）

	可以匹配路由条目，也能匹配数据流量
        ① 如果用于匹配路由条目，只能使用基础 ACL（2000—2999）
        ② 如果用于匹配数据包，可以使用任意的 ACL（基础、高级、二层、用户定义 ACL 等）2000—6999
	
	ACL 分类
        基本 ACL（2000—2999）一般用于匹配源 IP 地址
        高级 ACL（3000—3999）可以匹配五元组（源、目的 IP 地址；协议号；源、目的端口号）
        二层 ACL（4000—4999）可以匹配二层数据帧信息（源、目 MAC 地址；帧类型等）

	优点：
        ① ACL 可以灵活匹配路由（如：奇、偶数路由）
        ② ACL 可以匹配路由，也能匹配数据包（且匹配数据包时，能够根据数据包的特征 “如：五元组进行匹配“）
        ③ ACL 可以执行深度匹配（可以根据最长掩码、路由的 VRF 等信息进行优先控制）
		
	缺点：
        只能匹配前缀，当前缀一致时无法区分 “不同掩码的” 路由条目
	
	display acl all （查看acl匹配到的路由信息）

==================================

10.1.1.0/24
10.1.1.0/25
10.1.1.0/30

acl 匹配 10.1.1.0 0.0.0.3

10.1.1.0/24 可以变化的范围 0~255

10.1.1.0/25 可以变化的范围 0~127

10.1.1.0/30 可以变化的范围 0~3

0.0.0.3 都可以匹配上，因为10.1.1.0 的 0~3 范围包含了上面两个路由


	10.1.1.128/26 匹配不上
	范围是 128 ~ 255，不包含在 0~3 范围内
	
==================================
```

## 2、ip-prefix（IP 前缀列表）
```
    只能用于路由策略，匹配路由的前缀（从左往右匹配的），同时也能匹配掩码范围
	优点：
		匹配匹配路由前缀，也能匹配掩码
		（可以匹配前缀一致但掩码不同的路由，如：10.1.1.0/24 和 10.1.1.0/25 能够进行区分）
	缺点：
		只能匹配网络位，无法灵活匹配主机位
		（如：奇、偶数网段无法灵活匹配）
```

## 配置
### ACL 配置
```
	例1：
	配置方式（ACL）   ”匹配 10.1.1.0/24 位中的奇数路由“
	acl 2000
	rule permit source 10.1.1.1  0.0.0.254			// 10.1.1（固定） 0000 0001 中的 1 固定，其余可变

	例2：
	配置方式（ACL）   ”匹配 10.1.1.0/24 位中的偶数路由“	
	acl 2000
	rule permit source 10.1.1.0  0.0.0.254			// 10.1.1（固定） 0000 0000 中的最后一个 0 固定，其余可变

	例3：
	10.1.1.0/24						// 如何匹配 10.1.1.0/24、10.1.2.0/24、10.1.3.0/24 的路由
	10.1.2.0/24
	10.1.3.0/24
	10.1.4.0/24
	10.1.5.0/24		
	配置方式（ACL）
	acl 2000
	rule permit source  10.1.0.0  0.0.3.0			// 匹配 10.1.X.0  其中 X 的取值范围：0—3


————————————————————————————————————————————————————————————————————
```

### ip-prefix 配置
```
例1：			只需要匹配 10.1.1.0/25 的路由
	10.1.1.0/24
	10.1.1.0/25
	10.1.1.0/26

	格式：ip ip-prefix (名字) index （节点号） permit （前缀 + 掩码） greater-equal （>=掩码范围） less-equal （<=掩码范围）

	ip ip-prefix test index 10 permit 10.1.1.0 24 greater-equal 25 less-equal 25	// 匹配前缀为：10.1.1.0，掩码范围 =25 的路由
	
	
例2：匹配所有的 A 类地址（掩码为 8 的地址）
	ip ip-prefix test index 10 permit 0.0.0.0 0 greater-equal 8 less-equal 8	// 匹配任意路由，掩码范围 =8 


例3：如何通过一条 ip-prefix 匹配以下路由
	① 172.16.1.0/24
	② 172.16.2.0/25
	③ 172.16.3.0/26
	④ 172.16.4.0/27

	ip ip-prefix test index 10 permit 172.16.0.0 16 greater-equal 24 less-equal 27	// 匹配前缀为：172.16.0.0 且掩码范围：24—27 的路由


例4：如何一条 ip-prefix 匹配掩码为 24 的路由
	① 10.1.1.0/24
	② 10.1.0.0/16
	③ 10.1.1.0/30
	④ 10.1.1.0/26

	ip ip-prefix test index 10 permit 10.1.1.0 24 					// 代表只匹配 10.1.1.0/24 路由
——————————————————————————————————————————————————————————————————————
```

## 二、路由策略

### 1、filter-policy（过滤策略）
```
用于对 “路由” 进行过滤
		补充：使用路由策略过滤时，没有 permit 的路由，默认拒绝
	
filter-policy 在链路状态协议中，需要根据以下规则来进行路由过滤（OSPF、IS-IS）
----------------------------------------------------------------
	① 域内 LSA（1、2类）使用 filter-policy 无法针对 export 方向对路由进行过滤，因为 OSPF 协议不会传递路由信息，仅传 LSA 信息
				（总结：针对 1、2类 LSA 的 export 方向过滤，无效）

----------------------------------------------------------------
	② 域内 LSA（1、2类）使用 filter-policy 针对 import 方向的路由过滤有效，但只能针对本设备生效
			（例如：AR1 把 LSA 传递给 AR2，AR2 使用 import 方向过滤，可以针对 OSPF 路由进入全局路由表时生效，但仅对 AR2 有效）

--------------------------------------------------------

	③ 域间 LSA（3 类）“ABR 过滤 “ 使用 filter-policy 针对 import 方向的过滤有效
			① ABR 设备的全局路由表不会生成被过滤的路由条目
			
            ② ABR 无法把被过滤的路由转换为 3类 LSA
		（例如：AR4-AR3 为区域 1 设备，AR3-AR2 为区域 0 设备，AR3 针对 AR4 设备使用 filter-policy 进行路由过滤，AR3 和 AR2 都无法收到被过滤的路由）
			可以影响 AR3 本地设备路由表，也能影响整个区域 0 设备的路由表项

----------------------------------------------------------------

	④ 域间 LSA（3 类）“ABR 过滤 “ 使用 filter-policy 针对 export 方向的过滤无效，无法针对全局路由表把路由转换为 3 类LSA
				filter-policy 也无法针对 3 类LSA 进行出方向过滤

	（filter 工具能够代替 filter-policy 对 LSA 进行过滤）可以对 3 类LSA 在传递时做过滤
		AR2 与 AR3 属于区域 0、AR3 与 AR4 属于区域 1，AR4 有 X 路由，会被 AR3 生成 3类 LSA 传递到区域 0
		
        1. AR3 可以在区域 1 中使用 filter export（禁止 X 路由出去区域 1）对该 3 类 LSA 做出方向过滤
		
        2. AR3 可以在区域 0 中使用 filter import（禁止 X 路由进入区域 0）对该 3 类 LSA 做入方向过滤

----------------------------------------------------------------

	⑤ 域外 LSA（5、7 类）使用 filter-policy import 无法对外部协议的路由生效
		使用 filter-policy export 可以对外部协议的路由转换为 5 类 LSA 时生效，可以影响 5 类 LSA 的生成，影响整个 OSPF domain 收到该路由

================================================================

	filter-policy 在距离矢量路由协议使用（RIP、BGP）
        ① filter-policy export 可以针对本设备传递给其他对等体的路由信息生效，过滤路由后再进行传递
        
        ② filter-policy import 可以针对本设备接收路由时生效，过滤对等体传递给本设备的路由

	补充：BGP 还能针对单独邻居生效，peer X.X.X.X 后添加 filter-policy import 或 export
```


### 2、route-policy：
```
    可以对路由进行过滤，也能 修改路由属性（如：BGP 属性、优先级、开销值、下一跳等）
		”route-policy 无法直接使用，需要通过特殊的条件匹配“
		
		相比于 filter-policy（route-policy）可以修改属性，也能过滤路由，功能更强大
		
        但是缺点在于，无法直接调用，过滤范围没有 filter-policy 大（如：OSPF 的域间 LSA 无法过滤、域内也无法过滤）
```




## 配置命令
### filter-policy 配置
```
如：AR1 设备有路由 1.1.1.1/32 和 10.10.10.10/32

例1：  AR2 只能接收 AR1 的 1.1.1.1/32 路由
① 匹配路由
	acl 2000
	rule permit source 1.1.1.1 0				
    // 匹配 1.1.1.1/32 的路由

② 进入路由协议（AR2）
	bgp 100
	filter-policy 2000 import				
    // 接收路由时，根据 ACL 2000 规则进行匹配（只允许 1.1.1.1/32 路由进入）

② 进入路由协议（OSPF）（AR2）
	ospf 1
	filter-policy 2000 import				
    // 计算路由时，只允许 1.1.1.1/32 路由从 OSPF 路由表进入到全局路由表（只允许 1.1.1.1/32 进入）

```

### route-policy 配置
```
如：AR1 设备有路由 1.1.1.1/32 和 10.10.10.10/32
例1：  AR2 只能接收 AR1 的 1.1.1.1/32 路由
① 匹配路由
	acl 2000
	rule permit source 1.1.1.1 0				
    // 匹配 1.1.1.1/32 的路由

② 创建路由策略
	route-policy A permit node 10				
    // 创建路由策略，名称：A，节点 10
	
    if-match acl 2000					
    // 匹配对象为：ACL 2000 （1.1.1.1/32 的路由）
	
③ 进入路由协议（AR2）
	bgp 100
	peer X.X.X.X route-policy A import			
    // X.X.X.X 为 AR1 对等体地址，从 AR1 接收路由时执行 route-policy A 策略
								（只允许接收 1.1.1.1/32 的路由条目）
③ 进入路由协议（OSPF）（AR2）
	ospf 1
	filter-policy route-policy A import			
    // AR2 设备只允许 route-policy A 匹配的路由进入（1.1.1.1/32）


例2： AR1 为 ASBR ，可以把路由从 BGP 引入到 OSPF，也能把 OSPF 路由引入到 BGP （单点双向引入）
	AR1 的 OSPF 路由（1.1.1.1/32、2.2.2.2/32）
	AR1 的 BGP 路由（3.3.3.3/32、4.4.4.4/32）

	AR1 只能把 1.1.1.1/32 的 OSPF 路由引入到 BGP 协议中
	AR1 只能把 3.3.3.3/32 的 BGP 路由引入到 OSPF 协议中

① 匹配路由
	acl 2000
	rule permit source 1.1.1.1 0				
    // 匹配 1.1.1.1/32 的路由

	acl 2001
	rule permit source 3.3.3.3 0				
    // 匹配 3.3.3.3/32 的路由

② 创建路由策略（BGP）
	route-policy A permit node 10				
    // 创建路由策略，名称：A，节点 10
	
    if-match acl 2000					
    // 匹配对象为：ACL 2000 （1.1.1.1/32 的路由）

③ 协议调用（BGP）
	bgp 100
	import-route ospf 1 route-policy A			
    // 把 OSPF 进程 1 的路由引入 BGP 路由表时，调用路由策略 A（允许 1.1.1.1/32 进入）
——————————————————————————————————————————————————————————————————————		
② 创建路由策略（OSPF）
	route-policy B permit node 10				
    // 创建路由策略，名称：B，节点 10

	if-match acl 2001					
    // 匹配对象为：ACL 2001 （3.3.3.3/32 的路由）

③ 协议调用（OSPF）
	ospf 1
	import-route bgp route-policy B				
    // 把 BGP 路由引入到 OSPF 协议中，调用路由策略 B（允许 3.3.3.3/32 进入）




修改路由协议优先级（OSPF 为例）
① 匹配路由
 	acl 2000
	rule permit source 5.5.5.5 0				
    // 匹配 5.5.5.5/32 的路由

② 路由策略配置
	route-policy PRE permit node 10	
	if-match acl 2000
	apply preference 14					
    // 把 5.5.5.5/32 路由的优先级修改为 15

③ 调用策略
	ospf 1
	preference ase route-policy PRE 150			
    // 把 OSPF 外部路由的优先级修改为 150（其中 5.5.5.5/32 的路由优先级修改为 14）	


修改标签及过滤标签
① 放行路由并添加标签
	route-policy I2O permit node 10				
    // 创建路由策略 I2O，节点 10
	
    apply tag 100						
    // 允许路由通过，并添加标签 100

② 拒绝路由通过
	route-policy O2I permit node 5				
    // 创建路由策略 O2I，节点 5
	
    if-match tag 100					
    // 过滤带标签 100 的路由
```



### 例子：
```
AR1
    route-policy I2O deny node 5				
    // 把 IS-IS 路由引入到 OSPF 时，拒绝带标签 200 的路由
    if-match tag 200

    route-policy I2O permit node 10				
    // 把 IS-IS 路由引入到 OSPF 时，允许所有路由通过并添加标签 100
    apply tag 100				
    （注意：permit 必须在 deny 后面添加配置）
    （permit 为配置动作 “apply”）（deny 为匹配目的路由 “if-match”）


AR3 配置
    route-policy O2I deny node 5				
    // 把 OSPF 路由引入到 IS-IS 时，拒绝带标签 100 的路由
    if-match tag 100

    route-policy O2I permit node 10				
    // 把 OSPF 路由引入到 IS-IS 时，允许所有路由通过并添加标签 200

    apply tag 200		
    （注意：permit 必须在 deny 后面添加配置）
    （permit 为配置动作 “apply”）（deny 为匹配目的路由 “if-match”）	
```
